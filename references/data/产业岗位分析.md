# 产业岗位分析数据源（产业链归并口径）

> 用途：career-guidance 技能回答"某产业有什么岗位、门槛与薪资如何、大专生机会多大"时引用的数据源说明与复现手册。与 [岗位库数据源.md](岗位库数据源.md)（高职切片口径）同一岗位库、同一在招基数，本文件提供**产业维度**的归并口径与画像数据。
> 数据快照日期：**2026-09-23**（库为静态快照，在招基数 9,616,999 条与 2026-09-20 摸底完全一致；无新增抓取批次）。
>
> **⚠️ 文档状态（2026-09-23）**：第 1 节（口径）、第 5 节（复现 SQL）、第 6 节（局限）已定稿可用；**第 2–4 节数据表尚未跑出**——采集当日会话因离开公司内网与库断连（库仅公司内网可达，主机本身无故障），待回内网环境后按第 5 节 SQL 串行补跑并回填。补齐前，产业维度的引用暂用 [岗位库数据源.md](岗位库数据源.md) 第 5 节的产业链 TOP（细链口径、未归并到产业级）兜底，并注明"细链口径"。
>
> **引用原则（最高优先，用户口径）**：与岗位库数据源一致——库信息不全面（BOSS直聘为主、无真实发布时间、覆盖有偏），**只引用比例与结构**（占比、排序、分布），绝对条数仅作库内量级参考，不得外推市场总量。另加一条产业维度特有红线：**一岗可属多条产业链，产业之间占比不可相加、不可交叉对比绝对数**。

## 1. 产业维度口径（产业链树与归并方法）

### 1.1 链表树结构（`c_industry_chain_info`，共 13,310 条）

| 1 | 270 | 链条环节 | 上游、中游、下游 |

### 1.2 岗位挂链分布（`c_position_chain`，pc.deleted=0，共 21,631,418 链接）

| 挂链层级 | 链接数 | 占比 |
|---|---|---|
| 4 级 | 13,794,778 | 63.8% |
| 3 级 | 5,535,093 | 25.6% |
| 2 级 | 2,256,033 | 10.4% |
| NULL 级 | 150,514 | 0.7%（剔除） |

岗位**不直接挂产业（level 0）**，全部挂在 2–4 级细链上；归并方法＝沿 `pid` 逐级上溯至 level 0。本地全量校验：13,128 条 0–4 级链 100% 可归并到 98 个产业，无孤儿链 id；NULL 级 152 条链对应 0.7% 链接被剔除。

### 1.3 计数口径（引用数据时必须知道）

- 默认计数单位是**岗位×链关联数**（简称"关联数"）：一岗平均挂 ~2 条链（高职核心切片 2.07 条/岗）。同一岗位会在多个产业重复计入，因此**产业间占比不可相加**、对比绝对数无意义。
- **产业内结构**（学历/薪资/经验/岗位名/地域分布）用关联数计算：同一岗位在同一产业内重复挂链的情况极少，产业内比例可信。
- 在招口径与岗位库数据源一致：`publish_state='PUBLISHING' AND deleted=0`。

## 5. 复现 SQL（均需单条串行执行）

> **执行纪律**：归并聚合涉及岗位主表 1,156 万行 × 链表 2,160 万关联，单条预计 3–10 分钟——**一条一条串行执行，禁止并发**，避免多条重查询同时占用库主机资源；会话内先 `SET SESSION max_execution_time=590000;` 兜底（超时机制实测有效）。另注：**该库仅公司内网可达**（外网/家庭网络无法访问 192.168.8.x），跑数须在内网环境进行。连接方式与通用注意事项（字符集、勿 SELECT description 等）见 [岗位库数据源.md](岗位库数据源.md) 第 1 节。

归并 join 块（以下查询共用；沿 pid 上溯 4 级到 level 0 产业）：

```sql
FROM c_company_position p
JOIN c_position_chain pc ON pc.position_id=p.id AND pc.deleted=0
JOIN c_industry_chain_info c ON c.id=pc.industry_chain_id
LEFT JOIN c_industry_chain_info a1 ON a1.id=c.pid
LEFT JOIN c_industry_chain_info a2 ON a2.id=a1.pid
LEFT JOIN c_industry_chain_info a3 ON a3.id=a2.pid
LEFT JOIN c_industry_chain_info a4 ON a4.id=a3.pid
JOIN c_industry_chain_info l0 ON l0.id=COALESCE(
  IF(c.level=0,c.id,NULL), IF(a1.level=0,a1.id,NULL), IF(a2.level=0,a2.id,NULL),
  IF(a3.level=0,a3.id,NULL), IF(a4.level=0,a4.id,NULL))
WHERE p.publish_state='PUBLISHING' AND p.deleted=0
```

```sql
SET NAMES utf8mb4 COLLATE utf8mb4_general_ci;
SET SESSION max_execution_time=590000;

-- Q1 挂链层级分布（已跑通，秒级；NULL 桶即被剔除部分）
SELECT ic.level, COUNT(*) AS links
FROM c_position_chain pc LEFT JOIN c_industry_chain_info ic ON ic.id=pc.industry_chain_id
WHERE pc.deleted=0 GROUP BY ic.level ORDER BY links DESC;

-- Q2a 产业总览（关联数）
SELECT l0.id, l0.name, COUNT(*) AS links
<归并 join 块>
GROUP BY l0.id, l0.name ORDER BY links DESC;

-- Q3 学历结构（产业×学历）
SELECT l0.id, p.education, COUNT(*) AS cnt
<归并 join 块>
GROUP BY l0.id, p.education;

-- Q4 薪资中值分布（产业×中值；0=面议/空，999=中值>100K 脏值，中位数计算时两侧剔除）
SELECT l0_id, CASE WHEN mid>100 THEN 999 ELSE ROUND(mid,1) END AS rmid, COUNT(*) AS cnt
FROM (
  SELECT l0.id AS l0_id,
         (COALESCE(CAST(p.min_salary AS DECIMAL(10,2)),0)
          +COALESCE(CAST(p.max_salary AS DECIMAL(10,2)),0))/2 AS mid
  <归并 join 块>
) t GROUP BY l0_id, rmid ORDER BY l0_id, rmid;

-- Q5 热门岗位名（产业×岗位名，全量）
SELECT l0.id, p.name, COUNT(*) AS cnt
<归并 join 块>
GROUP BY l0.id, p.name;

-- Q5b 高职核心切片热门岗位名（产业×岗位名，education IN ('DAZHUAN','GAOZHI')）
SELECT l0.id, p.name, COUNT(*) AS cnt
<归并 join 块> AND p.education IN ('DAZHUAN','GAOZHI')
GROUP BY l0.id, p.name;

-- Q6 地域分布（产业×省份，来自企业地址）
SELECT l0.id, ad.province, COUNT(*) AS cnt
FROM c_company_address ad
JOIN c_company_position p ON p.company_address_id=ad.id
JOIN c_position_chain pc ON pc.position_id=p.id AND pc.deleted=0
JOIN c_industry_chain_info c ON c.id=pc.industry_chain_id
LEFT JOIN c_industry_chain_info a1 ON a1.id=c.pid
LEFT JOIN c_industry_chain_info a2 ON a2.id=a1.pid
LEFT JOIN c_industry_chain_info a3 ON a3.id=a2.pid
LEFT JOIN c_industry_chain_info a4 ON a4.id=a3.pid
JOIN c_industry_chain_info l0 ON l0.id=COALESCE(
  IF(c.level=0,c.id,NULL), IF(a1.level=0,a1.id,NULL), IF(a2.level=0,a2.id,NULL),
  IF(a3.level=0,a3.id,NULL), IF(a4.level=0,a4.id,NULL))
WHERE p.publish_state='PUBLISHING' AND p.deleted=0
GROUP BY l0.id, ad.province;

-- Q8 经验要求分布（产业×经验）
SELECT l0.id, p.experience, COUNT(*) AS cnt
<归并 join 块>
GROUP BY l0.id, p.experience;
```

薪资分桶口径与岗位库数据源一致：`<3K / 3-6K / 6-10K / 10-15K / 15-25K / 25K+`，剔除中值=0 与 >100K；分位数用加权线性插值。

## 6. 数据局限（引用时须知）

1. 继承岗位库数据源第 7 节全部局限（静态快照、无发布时间、无职位链接、BOSS直聘主导、爬虫批次时间等）。
2. **产业间不可加总**：一岗多链（平均 ~2 链），98 个产业的关联数之和大于在招基数；产业排名用关联数排序是"挂链热度"而非市场份额。
3. **产业链标签为库内映射**（`c_position_chain`），映射质量未逐条核验；NULL 级链 0.7% 链接被剔除。
4. **产业粒度不均**（1.4 节）：level 0 混合了不同粗细的产业概念，跨产业对比只看结构比例。
5. **地域来自企业地址**（`c_company_address.province`），非岗位办公地；连锁/多址企业会使地域占比略有偏移。
6. 产业岗位名 TOP 是**岗位名文本聚合**（同名不同 JD 合并），与岗位库数据源 TOP 同口径。
